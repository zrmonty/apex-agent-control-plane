# Gateway contracts

The Protobuf files are authoritative. Generated JavaScript and TypeScript declarations
live in `packages/apex-contracts-ts/src/gen`; do not edit them manually.

```powershell
pnpm --dir contracts install --frozen-lockfile --ignore-scripts
pnpm --dir packages/apex-contracts-ts install --frozen-lockfile --ignore-scripts
pnpm --dir contracts generate
pnpm --dir contracts test
pnpm --dir contracts verify
cargo test -p apex-control-plane-api --locked --test proxy_contract_json
```

Tool versions are pinned in both manifests and lockfiles. Generation uses local
Buf/protoc-gen-es binaries, not unpinned remote plugins. The optional platform Buf
package supplies the executable; package lifecycle scripts are unnecessary.
`verify` regenerates into an owned temporary directory, compares the entire output
inventory and bytes, then checks compatibility against the pre-change descriptor
from commit `1a6df0908de0a604415fd5c1631f697656d679ee`.
Updating that baseline requires a deliberate compatibility review, not a routine
generation run. The negative compatibility test reassigns an existing field number
and proves that the gate rejects it.

The frozen `event.proto` is built independently, unchanged. It and the legacy
`control.proto` contain separate definitions of `apex.v1.ControlAction`; combining
them in one descriptor set is invalid. The management generator selects its explicit
source inventory in `scripts/tooling.mjs`. Rust still uses the existing event crate.
Management ProtoJSON serialization is generated by pbjson; the legacy control
stream's `prost_types::Struct` transport is not replaced.

## Boundaries

- The browser RPC allowlist is generated only from `McpProxyService`, never the
  host runtime, governance or legacy command stream services. Listing a method does
  not advertise runtime support. Unwired handlers return `Unimplemented`.
- New runtime configuration carries the original control spec plus generation,
  a distinct HTTPS resource audience, schema/output profiles, explicit egress
  grants, telemetry policy and secret **references**, never credential values.
- TypeScript `decodeStrict` rejects unknown/duplicate protobuf aliases, unknown
  enum values, non-UUIDv7 mutation request IDs and noncanonical 64-bit numbers.
  It limits payloads to 256 KiB, 8192 fields/elements and 64 nested levels.
  Domain authorization and full runtime compilation remain server responsibilities.
  Rust transport consumers use `contract_json::decode_management_json`, which
  enforces the canonical integer profile and bounds using the generated descriptor.
  Generated serde alone implements general ProtoJSON and is not the strict
  management input boundary.
- 64-bit fields serialize as decimal strings, including trace values embedded in
  an event's existing JSON Struct. This follows the
  [ProtoJSON integer representation](https://protobuf.dev/programming-guides/json/).
  Neither JavaScript numbers nor millisecond-derived timestamps establish
  microsecond precision or cross-host accuracy.
- Generated files alone receive a readability exemption: exact package location,
  generator banner and content hash must match the generated manifest. CI
  independently regenerates and compares that manifest and all generated files.
  Handwritten code has no such exemption.

Fixtures intentionally contain non-routable example domains and secret references.
Rust tests pass the control fixture through the existing domain validator, then
both languages round-trip it and the trace fixture without precision loss.
These component checks are not live release evidence. Use the acceptance registry
and [release evidence ledger](../docs/operations/mcp-gateway-release-evidence.md).
