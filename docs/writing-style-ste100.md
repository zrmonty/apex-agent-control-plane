# Writing style: ASD-STE100

All Apex product documentation in this repository uses **ASD-STE100 Simplified Technical English**.

## Rules we follow

1. Use short sentences. Prefer one idea per sentence.
2. Use the active voice.
3. Use the imperative mood for procedures (Start, Set, Run, Do not).
4. Use the simple present for facts (The system writes events.).
5. Use the same approved term for one meaning. Do not switch synonyms.
6. Avoid long noun clusters. Split them when the text is hard to read.
7. Avoid informal words, hype, and marketing claims.
8. State limits clearly. Use *must*, *must not*, *can*, and *do not*.
9. Number procedure steps when the order is fixed.
10. Keep technical identifiers (`Apex.connect`, path names, env vars) unchanged.

## Scope

These rules apply to:

- `README.md`, `PRODUCT.md`, `Agent_Structure.md`
- Files under `docs/`
- Deploy and app `README.md` files that operators or developers read

These rules do not change code comments unless we update them on purpose.

## Reference

ASD-STE100 is the aerospace controlled-language standard for maintenance and technical manuals. We apply the same clarity goals to Apex operator and developer docs.
